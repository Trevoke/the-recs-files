# Brainstorming a change to skill text

Carries `UW-20261015-nkb5 §1, §2, §3: Realize a change to the system` and its
extension 1a, with skill text as the realization modality.

**Core principle:** the records are the only source of intent. A change to
skill text is a record section the text does not yet realize, or realizes
wrongly. A score, a failing eval, a reply that went wrong: each is evidence of
where to read, never the change to make.

## The process

**Read the records first (§1, §2, 1a):**
- Where the record keeper names a user workflow, or a step or extension of
  one, read it first and frame the change from it.
- Then read each record that bears: the user workflows and features the skill
  text realizes, the terms they use, the decisions behind them. Open each
  file; a title is never the evidence.
- Read the current skill text that realizes those records, under `skills/`,
  and the project's AGENTS.md for what it inlines.
- Cite each record the first time a reply refers to it, as AGENTS.md says.

**Settle the change (§3):**
- Ask one question at a time, multiple choice where it can be.
- State what the text misses as record sections: "`F-20261028-1mkt §4: The
  agent cites a record` has no sentence in `recs-writing-records` that
  carries it", with what that section says under it. Never as "question X
  fails" or "the score is 0.2".
- Where the record keeper brings a failing eval, read the records the eval's
  checks cite before the eval, and say which section each failure breaks.
- Each decision the change needs that no record holds is a record change:
  frame it as AGENTS.md "Framing a question" says, with an example, and wait.
  Write it with `recs-writing-records`. Nothing in the change rests on a
  proposed or rejected record.

**What comes out:** a short note of the records that bear, cited; what the
text misses, by section; the record changes agreed, each standing. Then
`recs-skills-writing-plans`.

## Keep apart

- An eval question and a record's example are two different things: a
  question never restates an example, and an example never restates a
  question. Where the change needs an example in a record, it goes in the
  record through `recs-writing-records`; where it needs a question, that is
  the plan's.
- A new word lands in no file before the record keeper agrees to it. Combine
  the words the records own first.
