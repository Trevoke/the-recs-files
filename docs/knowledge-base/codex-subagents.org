#+TITLE: How Codex spawns a subagent

Established 2026-10-19 from Codex's documentation and source, read on the web;
no run. Sources: https://learn.chatgpt.com/docs/agent-configuration/subagents
(where https://developers.openai.com/codex/subagents redirects), and openai/codex
at commit c953dacb42d2773d0ca9cc25a01129bba2ca36a8:
https://github.com/openai/codex/blob/c953dacb42d2773d0ca9cc25a01129bba2ca36a8/codex-rs/core/src/agent/role.rs,
https://github.com/openai/codex/blob/c953dacb42d2773d0ca9cc25a01129bba2ca36a8/codex-rs/core/src/tools/handlers/multi_agents_spec.rs,
https://github.com/openai/codex/blob/c953dacb42d2773d0ca9cc25a01129bba2ca36a8/codex-rs/core/src/agent/child_config.rs.

* The general-purpose subagent is the built-in `default` agent
"Codex ships with built-in agents": "`default`: general-purpose fallback
agent", "`worker`: execution-focused agent for implementation and fixes",
"`explorer`: read-heavy codebase exploration agent" (docs). role.rs declares
the same three, `default` described as "Default agent.".

* `spawn_agent` names the agent in `agent_type`
Its parameters are `message` (or `items`), `agent_type`, `fork_context`,
`model` and `reasoning_effort`; a second version takes `message`,
`agent_type`, `fork_turns`, `model` and `reasoning_effort`
(multi_agents_spec.rs). An unknown name fails with "unknown agent_type
'<name>'" (role.rs).

* Leaving out `agent_type` gives `default`, or the parent's type on a full-history fork
"/// The role name used when a caller omits `agent_type`." stands over
`DEFAULT_ROLE_NAME: &str = "default"` (role.rs). The first version's
`agent_type` reads "Omit to inherit the parent agent type with a full-history
fork; otherwise, `default` is used."; the second's reads "Omit unless
explicitly asked." (multi_agents_spec.rs). A full-history fork refuses an
`agent_type` with "Full-history forked agents inherit the parent agent type;
omit agent_type, or spawn without a full-history fork." (child_config.rs).

* A configuration can hide `agent_type` from `spawn_agent`
`expose_agent_type`, default true, removes the parameter when false
(multi_agents_spec.rs). What sets it false is not traced.

* A custom agent is a TOML file, identified by its `name`
"add standalone TOML files under `~/.codex/agents/` for personal agents or
`.codex/agents/` for project-scoped agents"; required fields are `name`,
`description` and `developer_instructions`; "Codex identifies the custom
agent by its `name` field"; a custom agent named as a built-in one "takes
precedence" (docs). Whether a plugin can carry one is not documented there.
