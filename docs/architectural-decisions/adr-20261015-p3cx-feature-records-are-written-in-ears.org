* ADR-20261015-p3cx Feature records are written in EARS
:PROPERTIES:
:STATUS: Accepted
:END:
** Context
A feature record is a spoke of a user workflow: it holds what a step
names, and never retells the steps. It is drafted by the agent and agreed
by a record keeper who may not be a developer, and it is superseded rather
than edited, so what changed between a record and its successor must be
plain. A Gherkin scenario's Given, When and Then form a small sequence with
an actor.
** Decision
We will write each feature record as a numbered list of EARS
requirements, one sentence each, in one of Mavin's five patterns, and not
in Gherkin.
** Consequences
A feature cannot retell its workflow, because an EARS sentence has no
actor and no sequence. Each requirement is a section a citation can name. A
feature record is never run as a test; tests are written from it.
