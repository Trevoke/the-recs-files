* ADR-11 Keep the order of the skills in a skill flow beside them
:PROPERTIES:
:STATUS: Proposed
:END:
** Context
The order of the skills is spread through their text, as instructions to
load another skill and as hand-offs. An orchestrator that runs skills as
separate units of work needs it in one place, and so does a reader checking
the skills against the user workflows.
** Decision
We will keep a skill flow, =skills/skill-flow.dot=: a Graphviz graph whose
nodes are the skills and the prompt templates they delegate. Each edge is a
load, a hand off or a delegate, and cites the user workflow step or
extension it realizes, ADR-9: The code realization skills are a prototype
adapted from superpowers, or both.
** Consequences
Rendering (ADR-10: Render each harness's package from capability markers
and a harness profile) checks every load and delegate capability marker
against the skill flow's edges, and every edge's citation against the
records on disk. Orchestrators read the order from the skill flow.
